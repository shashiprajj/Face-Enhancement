R5-8 — LOCAL-PATCH ARTIFACT DETECTOR
FINAL ENHANCEMENT SAFETY TASK

Repository: WelOrbit Face Enhancement Service (FES)
Current safe baseline: R5-6
R5-7 result: RED
R5-7 commit: 33922fe

OBJECTIVE
Determine whether the R5-7 NAFNet benefit/coverage improvements can be recovered safely by adding a deterministic local/spatial artifact detector.

R5-6 is the SAFE baseline and MUST remain the live/default state.
Do not promote R5-7.

WHY THIS TASK EXISTS
R5-7 materially improved NAFNet coverage and identity benefit, especially for full_image inputs, but the candidate returned at least 8 archive TEST faces with small rainbow/dotted patches. The existing global chroma guard could not reliably detect these localized artifacts.

The NAFNet model is NOT being replaced. This task is only about detecting the localized artifact failure mode.

HARD SCOPE
IN SCOPE:
- DEV-only artifact analysis
- deterministic local/spatial artifact features
- DEV labeling/inspection
- small local artifact detector
- isolated R5-7 research candidate
- regression tests
- one final service-level validation
- final report and commit

OUT OF SCOPE:
- new enhancement models
- GFPGAN/CodeFormer/SwinIR experiments
- NAFNet weight changes or retraining
- T6/RW gate redesign
- Feature-Match validation
- production deployment
- TEST/ztest/real-photo-driven threshold tuning
- endless follow-up tuning tasks

1. Verify current repository state.
2. Confirm src/, configs/, and tests/ are the R5-6 safe implementation.

4. Run a baseline smoke/regression check.

STEP 1 — RECOVER R5-7 AS RESEARCH ONLY
Recover the saved R5-7 candidate changes:
- relaxed artifact guard
- full-image framing correction
- reflect-padding correction, where applicable

Keep these isolated from the default/live service.
First reproduce the previously observed R5-7 benefit before adding the detector.

STEP 2 — DEV ARTIFACT CORPUS
Use DEV data ONLY for detector development.

Use the archive validation/DEV split and existing R5-5 DEV material.
Do not use archive TEST, ztest, or the 200 real photos to select thresholds.

Inspect broadly:
- legitimate NAFNet restorations
- high-chroma but legitimate restorations
- destructive outputs
- localized rainbow/dotted artifacts
- grayscale cases
- different blur strengths
- relevant face sizes

If DEV does not contain enough examples of localized artifacts to justify a detector, say so rather than inventing labels.

Labels:
- LEGITIMATE
- DESTRUCTIVE
- LOCALIZED_ARTIFACT
- UNCERTAIN

Do not silently classify uncertain samples as clean.

STEP 3 — INVESTIGATE SMALL DETERMINISTIC LOCAL FEATURES
Prefer simple interpretable spatial signals.

Evaluate a limited set such as:
- local chroma p99/p99.9
- local maximum vs global chroma distribution
- local-vs-global chroma excess
- high-frequency chroma concentration
- connected abnormal-region size/concentration
- spatial concentration ratio
- local chroma-to-luma ratios

Do not build an ML classifier unless deterministic signals clearly cannot solve the problem.

The goal is the SMALLEST defensible detector.

STEP 4 — DESIGN LOCAL GUARD
Desired flow:

input
 -> existing validation/detection/alignment
 -> existing NAFNet eligibility gate
 -> NAFNet
 -> existing artifact guard
 -> LOCAL PATCH ARTIFACT GUARD
 -> NAFNet output

If either guard or detector rejects/fails:
 -> ORIGINAL

Detector requirements:
- deterministic
- bounded runtime
- offline/no network
- no extra model
- grayscale-safe
- auditable reason/code
- detector exception => ORIGINAL
- no modification of accepted NAFNet pixels

Give it an explicit version identifier such as p5-nafnet-local-artifact-1.0.0.
Do not silently mutate the R5-6 guard version.

STEP 5 — DEV CALIBRATION
Report:
- total DEV samples
- legitimate/destructive/localized/uncertain counts
- artifact detection recall
- legitimate-output block rate
- retained NAFNet benefit
- fallback rate
- runtime overhead

Safety takes priority over coverage.
