1. This task is ONNX service integration and validation only.
2. Do not change model weights/architecture, detection/alignment, preprocessing, quality features, T6 safety logic, blur/input gates, routing thresholds, artifact guards, fallback policy, or public response semantics, except minimum inference-backend wiring.
3. Do not retune thresholds using the 200 real photos, archive TEST split, or ztest. They are validation sets, not tuning sets.
4. Record exactly which backend and model files were used for each run. Never silently substitute models.
5. PyTorch remains the default/live behavior unless the owner explicitly approves promotion after reviewing evidence. ONNX must be selectable with an explicit documented configuration. Invalid configuration must fail clearly; never silently switch backends.
6. Every ONNX inference error, timeout, invalid output, or resource failure must follow existing safe fallback behavior and return ORIGINAL with a clear internal reason. Never return a partially processed or unverified output.
7. Preserve existing endpoints and UI behavior. No UI changes unless strictly required to test existing behavior.
8. Keep changes small, reversible and isolated. No unrelated refactors, migrations or features.
9. Do not claim production readiness from synthetic/archive tests alone.

- GREEN: integration/parity sound; no material ONNX-introduced safety regressions in full-service real-photo validation; fallback works; trade-offs measured. GREEN means eligible for owner review, not automatic production promotion.
