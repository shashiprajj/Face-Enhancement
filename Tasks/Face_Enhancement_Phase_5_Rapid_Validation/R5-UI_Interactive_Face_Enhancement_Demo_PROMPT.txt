R5-UI — INTERACTIVE FACE ENHANCEMENT DEMO UI

PROJECT
Face Enhancement Service
Repository: D:\ReBIT\Face-Enhancement

OBJECTIVE
Build a simple local web UI that lets a user upload a face image, sends it through the EXISTING Face Enhancement Service at runtime, and displays the original image alongside the processed/enhanced result.

This is a DEMO / RESEARCH UI. Do not change the enhancement model, frozen gate, detector, or routing behavior.

CURRENT FROZEN STATE
- Current commit: 8b0b101
- Previous implementation baseline: 4ea2ed3
- Gate: p5-rwgate-1.0.0
- Gate seal: 78837a8d
- Enhancement model: A4 SwinIR-L
- R5-4 is blocked because actual Feature-Match is unavailable and real paired data is insufficient.
- Do NOT solve R5-4 in this task.

FIRST: INSPECT THE REPOSITORY
Before coding:
1. Inspect the FastAPI application.
2. Find the real `/v1/enhance`, `/health`, and `/ready` contracts.
3. Inspect existing tests and project structure.
4. Check whether a frontend already exists.
5. Choose the smallest maintainable local UI approach; do not assume a framework.

CRITICAL RULE
The UI must call the existing enhancement API/pipeline. Do not duplicate A4 loading, gate logic, detector logic, or enhancement logic in the frontend.

UI REQUIREMENTS

1. UPLOAD
- Drag/drop and file picker.
- Preview selected image.
- Validate supported formats and sensible max size based on backend capabilities.
- Replace/remove selected image.

2. ENHANCE
- `Enhance Image` button.
- Send image to existing `/v1/enhance` endpoint.
- Clear loading state.
- Because CPU A4 can take about a minute, show a truthful message such as: `Processing image… Enhancement may take up to a minute on CPU.`
- Do not fake progress percentages.
- Prevent duplicate submissions.

3. RESULT
Show side-by-side:
- ORIGINAL: uploaded image.
- PROCESSED: exact image returned by backend.
Optionally add a simple before/after slider if it is easy and clean.

4. STATUS / METADATA
Display only values actually provided by the backend, such as:
- ENHANCED
- ORIGINAL / NOT ENHANCED
- UNSAFE / NOT PROCESSED
- ERROR
- reason
- processing time
- detection/quality metadata if already exposed safely
Do not invent a new status vocabulary if the backend already defines one.
Do not expose secrets, model filesystem paths, or unnecessary internals.

5. RESET
Provide `Try Another Image` to clear upload/result/error state.

6. ERRORS
Handle invalid image, oversized file, backend unavailable, timeout, enhancement failure, unsafe/no-face, malformed response, and network failure.
Show friendly messages, not stack traces.

7. HEALTH
If practical, show Enhancement Service Online/Offline using existing `/health` or `/ready`.

8. UX
Clean modern internal ML demo. Keep it simple: Upload -> Enhance -> Compare.
No auth, database, accounts, analytics, Feature-Match, model selector, or threshold controls.

9. PRIVACY
Local-only research UI. No third-party image APIs, telemetry, or permanent storage unless already part of the existing backend contract.
Do not commit raw personal images.

ARCHITECTURE
Browser -> existing FastAPI `/v1/enhance` -> existing validation/detection/gate/A4/output guard -> API response -> Browser displays original + returned result + actual status.

API CONTRACT
If the current response lacks enough information for the UI to display its actual decision/reason, make the smallest backward-compatible response/schema extension necessary. Do not change enhancement decision logic.

CORS / LOCAL DEVELOPMENT
If frontend and API use different local ports, configure precise local development CORS. Do not weaken security unnecessarily.

TIMEOUT
Use a realistic frontend request timeout for CPU inference. Do not alter backend timeouts unless required and justified.

NO MODEL CHANGES
Do not change A4, weights, parameters, gate thresholds, p5-rwgate-1.0.0, detector, quality metrics, or add GFPGAN/CodeFormer/new models.

NO FEATURE-MATCH
Do not implement or fake Feature-Match. Do not add SFace/dlib matching to the UI. Do not claim an enhanced image is identity-matchable.

TESTING
Add focused tests for upload validation, API request, enhanced response, original response, unsafe response, errors, reset, any response/schema extension, and health if applicable.
Run relevant existing Face Enhancement tests and new UI/backend tests.

MANUAL SMOKE TEST
Actually run the app and test:
1. normal image
2. known poor-quality image
3. image expected to remain original
4. unsafe/no-face image if available
5. backend unavailable
Verify upload, request, loading, result, status, errors, and reset.
Use real runtime output, not mocked results, for manual verification.
