TASK R5-3 — TARGETED FIX + ROBUSTNESS PASS

Objective
---------
Fix only the problems demonstrated by R5-2 and prove that the service fails safely.

First principle
---------------
Do NOT redesign the system.

Use R5-2 evidence to identify concrete failures.

Examples
--------
If detection fails:
    -> fix detection/alignment.

If A4 preprocessing/postprocessing is wrong:
    -> fix that specific issue.

If the router sends an inappropriate degradation type to A4:
    -> make a targeted routing correction.

If Feature-Match integration is wrong:
    -> fix the integration.

If A4 produces a harmful result:
    -> keep the conservative fallback and document the failure.

Robustness test set
-------------------
Run a small deterministic matrix covering:
- good image
- blurry image
- noisy image
- tiny face
- no face
- multiple faces
- corrupted/truncated image
- very large image
- A4 inference failure
- timeout/hung inference
- repeated requests
- bounded concurrent requests

Expected behavior
-----------------
The service must never force a bad A4 output through the pipeline.

Examples:

A4 failure -> ORIGINAL
Detection failure -> safe fallback
Unsafe input -> ORIGINAL
Uncertain input -> ORIGINAL

Required work
-------------
1. Inspect R5-2 failures.
2. Select only high-value fixes.
3. Implement targeted fixes.
4. Add regression tests for every fixed failure.
5. Run robustness matrix.
6. Measure CPU stability/resource behavior.
7. Run the existing relevant regression suite.
8. Produce a concise report.
9. Commit changes.

Do not
------
- introduce a new enhancement model
- perform broad optimization
- expand the benchmark dramatically
- change unrelated project components
- declare production readiness

Acceptance
----------
No critical unsafe failure remains in the tested scenarios, and every tested failure mode has deterministic safe behavior.

Expected effort
---------------
Approximately 2–3 hours.
