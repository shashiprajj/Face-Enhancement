TASK R5-2 — SMALL REAL-WORLD FEATURE-MATCH EXPERIMENT

Objective
---------
Determine whether the existing enhancement approach actually improves the real Feature-Match system.

This is the most important task in Rapid Phase 5.

Population
----------
Start with approximately 100–200 real low-quality face images.

Prefer coverage of:
- blur
- noise
- low resolution
- compression
- mixed degradation
- good-quality controls

Use identity-linked reference images where available.

Do NOT spend time building a huge dataset.

Core experiment
---------------
For every eligible test image:

A) Original -> Feature-Match

B) Original -> Enhancement Service -> Feature-Match

Keep the Feature-Match system identical in A and B.

Do not retune Feature-Match just to improve the enhancement result.

Minimum measurements
--------------------
Record:
- original similarity
- enhanced similarity
- original match/no-match
- enhanced match/no-match
- original correct -> enhanced correct
- original wrong -> enhanced correct
- original correct -> enhanced wrong
- identity flips
- percentage routed to A4
- A4 failure rate
- detector failures
- safe fallbacks

Primary question
----------------
How many genuinely poor images that were previously difficult/unmatchable become successfully matchable after enhancement, without introducing unacceptable false matches or identity errors?

Important
---------
An embedding similarity increase alone is NOT enough.

The actual Feature-Match outcome is the decisive metric.

Required procedure
------------------
1. Build a deterministic manifest.
2. Verify identity separation.
3. Run Original -> Feature-Match.
4. Run Enhancement Service.
5. Run Enhanced/Original result -> Feature-Match.
6. Compare paired results.
7. Categorize wins, losses, unchanged cases, flips and failures.
8. Break down results by degradation type.
9. Preserve raw result manifests.
10. Write a concise evidence report.
11. Commit the experiment harness/results metadata.

Do not
------
- run another full synthetic benchmark
- use SFace/dlib as a substitute for Feature-Match
- change the production Feature-Match implementation
- tune the final router on the held-out evaluation images
- hide negative cases

Acceptance
----------
A reproducible real-world original-vs-enhanced Feature-Match comparison exists and clearly shows whether A4 is helping, neutral, or harmful.

Expected effort
---------------
Approximately 2–4 hours of engineering. CPU inference may run longer and should be allowed to run unattended.
